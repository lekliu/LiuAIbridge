# 一个轻量级 AI API 网关的实践：基于 Cloudflare Workers

> 大模型应用开发中，网络和多模型适配是绕不开的问题。本文记录一个开源网关方案的实践过程。

---

## 背景

在开发多模型应用时，我遇到了几个具体问题：

1. **网络不稳定**：国内直连海外 API 时常超时，本地代理方案难以用于生产
2. **SDK 维护成本高**：OpenAI、Gemini、Claude 各一套 SDK，参数、异常处理都不一样
3. **密钥分散**：API Key 散落在多个项目中，管理麻烦，也有安全隐患

调研了一些方案后，我选择基于 Cloudflare Workers 自建一个轻量级网关 —— LiuAIbridge，这里分享一下实践心得。

---

## 方案特点

### 1. 边缘部署，网络加速，解决地域访问限制

部署在 Cloudflare 全球 300+ 边缘节点，利用 Anycast 网络自动选路：

```
用户 → 就近边缘节点 → Cloudflare 骨干网 → 上游 API
```

**核心价值**：部署完成后，国内客户端无需配置任何网络代理即可直接调用 OpenAI、Gemini、Claude 等海外 API。开发者只需关注业务逻辑，无需维护复杂的网络出口。

实际测试数据（中国电信上海节点）：首字节延迟从 800ms+ 降到 150ms 左右，请求成功率从 70% 提升到 99% 以上。

Worker 到上游 API 的 TCP 连接复用率超过 90%，TLS 握手开销大大降低。

### 2. 协议统一，一套 SDK 打天下

支持两种调用模式：

**模式一：原生透传** —— 适合已有成熟代码，只需要解决网络问题
```bash
# OpenAI 原生
https://你的域名/openai/v1/chat/completions

# Gemini 原生
https://你的域名/google/v1beta/models/gemini-1.5-flash:generateContent
```

**模式二：OpenAI 兼容格式** —— 适合多模型场景
```python
from openai import OpenAI

# 用 OpenAI SDK 调用 Gemini
gemini = OpenAI(
    base_url="https://你的域名/compat/openai/google/v1",
    api_key="BRIDGE_TOKEN"
)

# 用 OpenAI SDK 调用 Claude
claude = OpenAI(
    base_url="https://你的域名/compat/openai/anthropic/v1",
    api_key="BRIDGE_TOKEN"
)
```

**流式转换实现**：Gemini 流式返回是 JSON 数组格式，网关层用括号平衡算法识别完整 JSON 对象，实时转换为 OpenAI SSE 格式，前端代码不需要任何修改。

### 3. 多密钥管理，可视化操作

每个服务商可以配置多个 API Key，系统基于全局请求计数取模实现轮询负载均衡：

```typescript
const globalCount = parseInt(await KV.get(`STATS:${service}`) || "0");
const selectedKey = activeKeys[globalCount % activeKeys.length];
```

管理后台提供：
- 多 Key 增删改查
- 一键启用/禁用
- 成功/失败统计
- 最后活跃时间追踪

## 5 分钟快速部署

整个部署过程非常简单，记录一下关键步骤：

**Step 1: 安装 wrangler**
```bash
npm install -g wrangler
wrangler login
```

**Step 2: 创建 KV 命名空间**
```bash
wrangler kv namespace create LIU_BRIDGE_KV
# 把返回的 id 填入 wrangler.toml
```

**Step 3: 设置 Secrets**
```bash
wrangler secret put ADMIN_TOKEN   # 管理后台密码
wrangler secret put BRIDGE_TOKEN  # API 调用令牌
```

**Step 4: 部署**
```bash
wrangler deploy
```

部署完成后，访问 `/admin` 进入管理后台配置 API Key 即可。
